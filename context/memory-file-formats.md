# メモリファイル形式

## .local/ 全体構成

```
.local/                          # MEMORY_DIR（PJ CLAUDE.mdで定義、デフォルト: .local/）
├── memory/                      # タスクごとのメモリディレクトリ
│   ├── YYMMDD_auth-feature/     # YYMMDDは実際の日付（例: 260112 = 2026/01/12）
│   │   ├── 05_log.md
│   │   └── ...
│   └── YYMMDD_bug-fix-123/
└── issues/                      # codebase-reviewで生成されるissueファイル
    ├── critical-sec-ユーザー入力のSQLインジェクション脆弱性.md
    ├── major-perf-ページ一覧取得でN+1クエリが発生.md
    └── ...
```

## メモリディレクトリ構成

場所: `${MEMORY_DIR}/memory/YYMMDD_<task_name>/`
- MEMORY_DIRはPJ CLAUDE.mdで定義（デフォルト: `.local/`）
- **YYMMDD**: システムプロンプトの`Today's date`から取得した実際の日付（年2桁+月2桁+日2桁）
- task_nameはタスクを識別する短い名前（例: `auth-feature`, `bug-fix-123`）
- **IMPORTANT**: 例示の日付をコピーせず、必ずシステムプロンプトの日付を使用すること

| ファイル | 用途 | 作成タイミング |
|---------|------|--------------|
| 00_spec.md | 機能要求・要件定義 | タスク開始時 |
| 05_log.md | ユーザー指示とレスポンス・実施内容のログ | タスク開始時（随時追記） |
| 10_task.md | タスク一覧 | 要件定義後 |
| 20_survey.md | 調査結果 | 調査完了後 |
| 30_plan.md | 実装計画 | 計画立案後 |
| 40_progress.md | 実装進捗 | 実装中（随時更新） |
| 60_decisions.md | チーム意思決定ログ（質問フェーズ専用） | 実装中（チームメンバーが決定を下すたびに追記） |
| 80_review.md | レビュー結果 | レビュー実施後 |
| 90_pr.md | PR内容 | PR作成時 |
| 99_history.md | 意思決定ログ | 随時 |

## 05_log.md（重要）

ユーザーからの指示とそれに対するレスポンス・実施内容を逐一記録:

```markdown
# 作業ログ

## YYYY-MM-DD HH:MM - 初期指示

**ユーザー指示:**
> [最初の作業指示をここに記載]

**レスポンス:**
- [実施したこと1]
- [実施したこと2]

---

## YYYY-MM-DD HH:MM - 追加指示

**ユーザー指示:**
> [追加の指示]

**レスポンス:**
- [実施したこと]

---
```

**agent review呼び出し時**: このファイルのフルパスを明示し、agentに中身を読ませる

## 60_decisions.md（質問フェーズ専用）

**IMPORTANT: このファイルは指示者質問フェーズ（orchestrator Step 8）専用です。他の用途に使用しないでください。**

チームメンバーが下した意思決定を記録し、質問フェーズでユーザーが妥当性を検証するために使用する。

```markdown
# チーム意思決定ログ

## 用途

このファイルは指示者質問フェーズ（Step 8）専用です。
各チームメンバーが下した意思決定を記録し、ユーザーの回答と照らし合わせます。
**他の用途（監査、レビュー等）には使用しないでください。**

## 意思決定一覧

### D001: {決定の概要}

| 項目 | 内容 |
|------|------|
| **決定担当** | {グループ名}・{ロール名} |
| **決定時刻** | YYYY-MM-DD HH:MM |
| **Stepフェーズ** | Step {N}: {フェーズ名} |
| **決定内容** | {具体的な決定内容} |
| **根拠** | {なぜその決定をしたか} |
| **検討した代替案** | {他に検討した選択肢。なければ「なし」} |
| **質問ステータス** | 未確認 / 確認済み / 要修正 |
| **ユーザー回答** | {質問フェーズでのユーザー回答。未確認なら空欄} |

---

### D002: {決定の概要}

...

## 質問フェーズ結果サマリー

| ID | 決定内容 | 決定担当 | ステータス |
|----|---------|---------|-----------|
| D001 | ... | ... | 確認済み |
| D002 | ... | ... | 要修正 |
```

### 記録すべき意思決定

以下のような決定を記録する:

| Stepフェーズ | 記録すべき決定例 |
|-------------|----------------|
| Step 1（ストラテジー会議） | グループ分割の決定、グループの数と構成 |
| Step 2（ドメイン分析） | グループの命名、ドメイン範囲の確定 |
| Step 4（意見収集） | 技術選定、アプローチ選択 |
| Step 5（事前評価） | 事前評価担当(Pre-Assessor)の評価結果、規模判定 |
| Step 6（ロールの実行） | 設計決定、実装方針、テスト戦略 |

### 質問フェーズでの使用方法

1. PMは60_decisions.mdを読み込む
2. 各決定について、AskUserQuestionでユーザーに確認
3. ユーザーの回答を「ユーザー回答」欄に記録
4. ステータスを更新（確認済み / 要修正）
5. 「要修正」の場合は修正を実施
6. 全決定が「確認済み」になるまでループ
